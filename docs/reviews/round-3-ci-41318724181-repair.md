## 失败原因、产品修复与规格依据

### 1. SE 键盘遮住释义保存按钮

失败用例 `testLiveColdStartImportReadingLookupPersonalMeaningReviewAndRestart`；原生录像和 AX 显示：个人释义已输入，键盘仍有焦点，保存按钮位于输入辅助栏遮挡范围，没有进入保存成功状态。不能把此失败归为数据库失败，也不能通过延时或伪造成功反馈解决。

将唯一保存操作从 Form 行移到导航栏，视觉文字为“保存”，无障碍名称保留“保存个人释义与笔记”，小屏键盘打开时可访问。保存意图先结束编辑，成功标签仍只在真实 Repository 写入和读回均成功后出现；失败显示原错误并保留草稿/重试。

依据 SPEC §9.2：“点击词卡进入详细词典页。”及 §30：“**真实失败必须可见**：网络、数据库、签名或 AI 失败不能被伪装成成功。”沿用既有个人释义/笔记功能与持久化路径，不更改答案规则。

强化真实冷启动 UI：键盘存在时保存按钮必须可点击；保存后键盘消失；退出详情再打开，个人释义必须从持久化读取后与输入一致。原保存成功断言、后续真实复习/解锁/重启流程均保留。

证据：[SE 原始产物](https://github.com/whyhaoyu1022-glitch/LexiDawn/actions/runs/41318724181/artifacts/13088667534)，AX `9F7E6AC6-E5F4-4D56-A292-C167DC9D6970.txt`，原始录像 `DD3A69A9-4EEE-4A7C-A13A-03562083C561.mp4`。录像帧仅用于定位，不冒充交付 PNG。

### 2. 文章库重置点击同时触发打开文章

失败用例 `testExploreCardsFavoritesAndConfirmedResetPreserveNativeReadingFlow`。失败 AX 中同时出现库中的“重新标记为未开始”和新打开的“英文阅读”页面：同一 List 行中的默认自动按钮样式让重置点击同时触发打开动作，确认框未能正常显示。

文章行显式使用 borderless 按钮样式，各动作独立；收藏/稍后原有 bordered 样式保留。确认框使用 presenting 捕获文章快照，避免系统关闭绑定后再读取空的 resetting；只有明确确认才调用原归档重置事务。每日任务限制和原历史保留规则不变。

依据 SPEC §5.5：“意外打开后立即退出的情况可以允许用户在文章信息菜单中选择"重新标记为未开始"，但必须确认并重置该文章的探索状态；不应自动把它重新塞回列表。”

强化 UI：确认按钮真实出现；没有误开阅读器或原文编辑页；先取消并确认仍在库中、再明确确认；原推荐卡重新出现断言保留。原生截图 X02 仅在确认框真实存在后捕获，不能将失败页面标成确认成功。

证据：[full-1 原始日志及 xcresult](https://github.com/whyhaoyu1022-glitch/LexiDawn/actions/runs/41318724181/artifacts/13088672741)。运行取消后结果包未最终完成，不能当作完整截图交付。

原用例 `testRound2ReadingLookupVocabularyReviewAndExploreUnlock` 已完成真实周期，随后期待的“暂无合法探索内容，可先导入文章。”不再存在。保留原断言；空候选池恢复该说明，同时保留标题“正在寻找新文章”及发现/重试入口。仅筛选无结果时继续显示调整筛选的说明。
