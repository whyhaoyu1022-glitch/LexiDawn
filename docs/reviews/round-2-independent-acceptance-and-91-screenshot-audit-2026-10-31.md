## 1. 阻断、功能缺口与质量风险清单

**严重级别定义**：P0＝已确认破坏核心流程/重大数据或安全风险；P1＝本轮要求未达到或具有明显用户可见缺陷，修复前不能称完整交付；P2＝质量/易用性/可靠性风险；P3＝审美和文案微调。对仅来自截图的异常，不能推断其必然是每次旋转的持续性 Bug。

### A-01 | P1 视觉功能缺陷：横屏阅读器严重异常（截图 P25）

**证据**：原始截图 P25-real-rfc-landscape.png，横屏切换后大面积纯黑，上方无正文，下方标题区出现白色/暖纸色但正文区域为空。README 对异常已有披露；这不是审核方虚构。UI 测试 testGalleryRealRFCReaderAppearanceAndOrientation 在 LexiDawnUITests.swift 第431–434行只设置方向、检查 finish-reading 按钮存在、抓图、立刻切回竖屏；未检查 reader-body、实际可见字数、文本命中、内容区域 CGRect、稳定等待或旋转前后状态。

**影响**：目前不能把 SPEC §6、§24.6 的横屏适配标记为通过。可能是截图时序/Simulator 重绘/方向配置，也可能是 EnglishTextContainer+TextKit 布局，但任何一种都应复现并留下布局证据。

**整改验收**：在横屏至少等待两次稳定布局帧或业务可见条件；断言正文英文词/正文区确实在窗口内、可滚动、可点词、内容背景正确、返回再旋转时保留进度；记录 window/view bounds、safeArea、contentSize、contentOffset 和截图。最少连续10次旋转，另测深色主题、键盘弹出状态和小屏/iPad。定位源代码：InteractiveEnglishText.swift 第14–52行与 ReaderFeature.swift 第52–111行。

### A-02 | P1 确认交互缺陷：完成的中文配对项未禁用（S13/S14）

**证据**：S13、S14 已配对英文 internet 呈灰色勾选，但匹配的中文按钮仍为粉橘色。ReviewFeature.swift 第41–60行中左侧英文有 .disabled(question.completed)，右侧含义按钮没有同等限制；对已完成的含义再次点击仍能调用 submit(questionID:selected, answer:option.senseID)。

**影响**：用户可将已经用掉的中文再次误配给剩余英文；选项语义不清，还会记录无意义的错误尝试并影响复习评分。底层答案保护不能代替 UI 禁用。**修复应在 UI 与 Service 双层检验配对项是否已被占用。**

**整改验收**：匹配成功后两列对应项同时锁定/退场，仍可清楚回看完成项；触控、VoiceOver、快速重复点击均不能再次消费已使用的含义；错误配对后允许正确恢复，尝试计数正确；新增 UI 自动化。

### A-03 | P1 产品完成度：真实内容源只有一个固定 RFC，不是成熟多主题文章池

ContentRepository.swift 第84–102、208–228行及 LearningRules.swift 的 SourceRegistry 仅真正接入 RFC 8890，并使用固定正文 SHA 核验；生产首次启动内置 RFC，用户也可合法导入自有文章。这符合上一轮要求的“至少一个合法真实来源”的底线，**不得把它误判为伪造文章**。但 SPEC §12.1–12.8、M3 的来源登记表、多来源排序、1200–2500词主题候选、事件去重等尚未充分实现。单 RFC 一旦指派完成，后续日期如果用户不导入，自动候选池可能耗尽。只有一个标题和单一内容来源，不能宣称长期每日英文阅读推荐已经完成。

**整改**：继续接入多个经过许可核验的官方源/合法 API，建立真正多源配置与缓存策略、主题质量评分；证据应包含许可的具体权利而非只证明 URL 可访问。没有新许可不能乱加数据；未完成时文档标明 M3 部分交付。

### A-04 | P1 产品完成度：英语词典/语境义与短语不满足完整 SPEC

VocabularyRepository.swift 第124–169行用本地 CC-CEDICT 中英词典反向索引，确实有来源许可证而非虚构数据；ReaderFeature.swift 第198–279行的浮窗/详情明确承认可能含义、不提供英语 IPA/词性。可是 SPEC §7.2–7.4、§8.2–8.5/M4 要求当前语境义优先、词性/音标、真实词义结构、短语识别、用法、代表性例句及同义词辨析。现在只有候选中文字形的反向对应，不是可靠的英汉语境字典；多词短语、变形短语与义项排序未形成完整能力。

**整改**：明确本轮为基础词级查词，不要把 M4 完成；寻找可合法商用/缓存的英英或英汉结构化词典源，加入语境消歧与短语识别，可在无可信数据时持续显示不确定性标记。英文词已加入生词本却缺正确义项时不应生成错题。

### A-05 | P1 范围缺口：复习算法与附加模式尚未交付

ReviewRepository.swift 第1–185行建立真实持久化会话、答案、日志与排程；SPEC §10 两阶段的最低闭环已有。排程使用 LearningRules.swift 的 lexidawn-basic-1（Again=1天、Hard≥2天、Good≥4天等），开发方明确不称为 FSRS，诚信良好。但 SPEC §10.5/10.6 的完整题型丰富度、§10.7 的成熟遗忘曲线建模、§10.8 的额外复习轮和按 §19.7 设计的更多成熟复习状态未交付。界面仅有基础文字与按钮配对、单词掩码，尚缺句子级拼写上下文。

**验收建议**：基础闭环可记部分通过；正式 M5 与“真正 FSRS/全部题型/额外复习”保持未完成状态，不能以测试数量替代规格覆盖。优先修 A-02，再补正确词义、题组解释和拓展。

### A-06 | P1 生产端到端证据不能由隔离截图替代

P01–P17 是生产 RFC 的首次启动、阅读/点词，不是从生产空库自然积累多个词并完整复习直至解锁。S 为真实 RFC 正文加**预先种入**个人释义/复习状态；F 为**隔离的原创/测试文段**，演示完整周期。两者有价值，但与生产真实数据的全程冷启动 E2E 不同。SPEC §24.1/§25 要求从真实初始状态成功完成闭环；现有 CI 真实执行的 UI 测试是强证据但不能直接推广到广泛真实文章来源或非预置词条。

**验收**：补从纯生产初装、真实合法文章、真实点击词、用户手动补可靠义项、创建两阶段复习、完成原始周期、跨日续接且无测试注入的端到端证据；可在隔离存储运行但必须明确没有预置生词或完成状态。

### A-07 | P2 许可撤回后的长时打开行为需补足

ContentRepository.read（142–177行）每次读取会重新检查高水位/到期并保留历史，已较上一轮完善；ReaderFeature.swift 第105–116行有过期日期任务检测与场景阶段恢复，X10–X12 证明一个定向到期场景处理成功。不过目前没有证据证明页面保持打开、外部内容许可被临时撤回、系统日期提前/回拨和离线返回时都能及时撤销屏幕上已有正文。**这是高风险未验证，不是已经发现非法显示**。

**验收**：动态短期到期、App 后台恢复、网络不可用和未来时间回拨用模拟时钟进行测试，正文显示权限需与继续阅读隔离并保留用户核心记录。

### A-08 | P2 评论区般的技术提示与真实复习屏幕体验过于简陋

截图 S10–S19、F25–F27：两个列均为淡色圆角按钮，没有明确的“选中—连线—已配对”运动反馈；错误提示太轻、缺明显定位；拼写屏幕没有真实例句语境，有大量空白而底部键盘区域拥挤；基础排程说明占据首屏。SPEC §10.5/10.6 的学习友好反馈需要加强。建议采用有编号/边框/符号的双列匹配、正确配对动画与语义强调，提示和答案保持在键盘上方安全区域。

### A-09 | P2 阅读器背景与主题不统一（P20–P24）

P21 的正文黑底但其上 SwiftUI 标题、导航、按钮区域仍为白底，强烈割裂；P22 暖纸色仅作用正文。ReaderFeature.swift 第64行只将 theme 传递给 InteractiveEnglishText，InteractiveEnglishText.swift 第41–48行只设置内层 UITextView 背景色/字体前景，缺对整个阅读器容器、导航栏、状态栏、空态、弹窗进行统一的主题管理。**这是确认的视觉实现问题**。同时注意白底纸色之间的硬边界及夜间亮屏刺激。

**验收**：阅读器及导航统一响应主题、支持系统切换、颜色对比测试、长文章回到正文不白闪；手动切换后重开/后台恢复仍一致。

### A-10 | P2 默认阅读正文存在过大空白与排版密度问题

P03、P20、P26、F08 等的正文开头与顶部进度条之间留白很大，尤其短文章空区明显；P09–P11 RFC 从原始纯文本保留硬换行，英文表现为短行/不均匀的句块。忠实保留官方未修改原文合理，但可以在不改变原始存储字节的前提下设计合规展示层（须确认 IETF TLP 对派生/重排的范围），或至少减少顶部冗余间距、建立明确正文容器分隔、保留源文本原始查看路径。不能以删除版权声明换取美观。

### A-11 | P2 全局低对比和视觉系统尚不达 SPEC §16 的成熟度

首页 Hero 的大标题和白底适合品牌，但辅文大量采用过淡灰色/浅橙色；按钮、错误文案和完成状态在截图中难辨，任务清单被长来源文字挤压；复习、探索、词汇和设置页多为系统默认白列表+薄灰卡，欠缺统一的 Liquid Glass 设计语言和精致的层次。建议按可读性优先建立语义颜色、最小字号/对比门槛，增加动效克制的反馈。总体视觉可用但距离“精致、温暖、现代原生阅读产品”仍有差距。视觉评价属主观建议，与功能 bug 分开报告。

### A-12 | P2 正式设置与许可页信息架构不佳

P30–P35 中部分设置与版权说明字号偏小，许可内容近乎未经排版的整块纯文本；用户很难确认“来源/展示权利/缓存/署名”差异。应拆分为来源卡、许可名称、可点击许可网址、当前权利/限制、获取日期、失败解释、可复制引用。设置开关变更应明确当前生效范围，不将“AI/通知准备中”包装为已启用。

### A-13 | P2 复习评分的可解释性和答案来源还有不足

ReviewRepository.swift 第115–156行对 Again/Hard/Good 的映射是实际确定性的，且日志有保存；但 UI 中“显示答案→Again”反馈停留在很浅的文字，没有下一次到期时间、得分原因、是否影响已完成项或正确中文证据。反向 CC-CEDICT 可能产生多个未消歧的中文对应词，当前算法取首次匹配中文进行训练，不能无条件视作‘这个单词在文章中唯一正确含义’。建议引入确定来源的学习 sense，用户可以查看/更正，并在题目页面标明用户释义或词典来源。

### A-14 | P2 UI 自动化对横屏/动态字体/复杂无障碍的断言不够

目前 20 个真实 XCUITest 已通过，覆盖面较此前明显扩展；但横屏 UI 测试仅按按钮存在性检查、未断言正文稳定。VoiceOver 可见 token 无障碍是自行构建 UIAccessibilityElement（InteractiveEnglishText.swift 第105–124行），其焦点移动、滚动后重新创建元素、最大辅助字体和高对比均未在真机或完整自动化中证实；内部可见字形刷新也被 0.3 秒节流。应补词元焦点、朗读顺序、动态字体最大档、两行词/括号命中、小屏横屏键盘的专门回归。

### A-15 | P2 本轮截图包不能作为全部异常真实复现的证明

X13 是预置 HTTP429 退避记录，不是截图时真实远端返回429；X10–X12 是人为缩短期限，不表示 RFC 真实许可已过期；storage-unavailable 是故障注入；F 为测试原创。截图说明文件有诚实标注，这是良好实践。报告和宣传必须保留这些标签，不得将上述情景描述为生产线上自然发生的故障。

### A-16 | P2 文档/范围仍有历史状态交错

STATUS.md、需求追踪矩阵等保留 Round 1 历史“生产未接入”的旧段落，Round 2 新段落再说明当前已经接入。历史记录不应删除，但给新接手者阅读造成歧义；建议在文件顶端增加显著 CURRENT 状态总表，区分历史条目。Round 2 自述在第7节提供了应用代码 run 41194434948 的 93/13 成功，但这次截图补充后的最终 aa802 的结果确实是新的 93/20 成功；应以当前 SHA 和运行号为最新证据。README/STATUS 中“截图结果待核对”需要在后续文档更新时最终封口。

### A-17 | P2 单次错误/重试操作与可恢复性风险

ReviewFeature.swift 第78–104行 load() 在异步重新装载时未系统性清空上一次 selected、spelling、feedback 或 emptyResolved，且没有统一操作序列 token；跨周期/会话变化可能让旧答题反馈和选择遗留到新题组。属于静态代码推断的高风险，不是用户截图已复现的实际 bug。应建立 per-session UI 状态重置策略并补连续切换周期、重复重试与长时间后台恢复测试。

### A-18 | P2 词典词条缓存在资源更新时缺清楚的版本失效策略

VocabularyRepository.swift 第142–169行查询词典时优先读取持久化缓存，CEDICTDictionaryProvider 通过 Bundle.main 加载静态 JSON。DictionaryEntryRecord 没有根据新 bundle 资源版本驱动失效/迁移的完整路径；以后词典版本更新可能长期展示旧义项。现阶段固定版本可用，但应按 SPEC §19.5 / §20.2 增加来源版本比较、缓存权限期限与迁移测试。

### A-19 | P2 缺真实深度性能证据

Round2Tests 中有 3500 词 token 命中微基准，但这不是在实际 UI 以长文高频滚动时测得的稳定 FPS/内存/主线程延迟。P09–P11 实测滚动通过，但不能宣称 3500 词稳定 60fps。需要 Instruments/Time Profiler/Memory Graph、不同型号滚动和弹词时内存曲线，尤其 TextKit 无障碍可见 token 元素重建及整页文本布局。

**随后提升产品完成度**
