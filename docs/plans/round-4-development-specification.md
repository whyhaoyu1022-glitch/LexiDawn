### 2.1 不可牺牲的数据不变量

1. 最早未完成周期优先续接；新发现文章不覆盖旧任务；每日分配原子且不重复。
2. 阅读与复习独立；书库、收藏、稍后、历史和探索不能绕过当前任务门禁。新入口只增加可发现性，不增加访问权限。
3. 生词、个人义、笔记、明确选义、上下文、历史日志与排程不随缓存清理或UI精简删除。只撤销本次真实新建的加入，不误删原有词。
4. 原文与结构原子一致；清理非文章控件不是删节记者正文；存储完整性不明的新候选仍丢弃。
5. 写入失败无成功勾号、无“已保存”、无虚假完成；失败事务不留孤立题组/词条或错误门禁。
6. 弱中文候选不能因“有字符串”就成正确答案；用户明确延期也必须与真实作答、原始队列为空分别记录。

### 3.2 可测量的设计约束

这些是开发执行的初始设计合同；图中表达的核心布局优先，不能用数字机械挤压内容。

- 信息层级：文章标题使用今日主任务的系统衬线字族；探索卡默认约20–24pt，主任务约24–28pt，常规正文遵循用户阅读设置；词头20–24pt、元信息12–14pt，全部使用可缩放文本样式。辅助字号可增高/换行，不能硬缩字号藏内容。
- 一篇文章一个主要外框；常规卡内边距16–20pt、圆角18–24pt、行间8–12pt。主题色集中定义，禁止在每个View散落条件色值。
- 渐变卡必须用足够稳定的暗/亮蒙层保证文字可读，普通文本目标对比度≥4.5:1，大标题/关键非文本图形≥3:1；按最差渐变位置测量，不能只测平均颜色。
- 主次按钮有边界与明显状态，触控命中区至少44×44pt。成功/错误除了颜色还有图标和文本；红色用于错误或破坏动作，不把大段说明都染成操作色。
- 不沿用固定52pt来猜所有设备Tab/键盘高度；使用真实safe area与容器布局。滚至底部时最后可操作控件应完整位于Tab/键盘可见区域上方，留至少约12pt可读间距。
- 窄屏、大字与横屏优先单列；标准元信息是一条逻辑行，大字允许换行。长标题不省略到无法识别，控件不相互挤压。
- 小查词卡正常字号目标约240–320pt宽、140–180pt高；可用空间不足时位置/高度自适应，仍保持“小而简”的意图。辅助大字下以内容可读和操作可达为准，不能强行裁切成固定高度。
- 默认界面去除“负责人指示”“完整性重新检查”“不会伪造”等开发/合规自述、重复版权块、原始时区代码和全量排程日志；真实错误、用户需要的来源/状态、许可入口保留在合适层级。

### 3.3 图外可同步优化的有限范围

允许：统一标题/间距/颜色、缩短空/加载/失败文案、清理重复导航与“重新读取/重试”、避免浮动Tab覆盖最后一项、整理统计口径至帮助详情、在同一设计系统下改善未标注页面。每项必须能说明与21图体验的关系，并有回归截图。禁止借机推倒架构、换UI框架、增加AI/付费API/账号/云同步/通知或全新产品模块。额外美化不能代替任何一张原反馈的关闭证据。

| R4-A24-11 | 完成阅读/真实复习或明确合法延期后门禁按已有规则处理；收藏、选义、填写、加入、Provider返回本身均不能算复习完成。 |
| R4-A24-12 | 可靠词和无可靠来源自建词各有完整原生E2E/重启/离线/失败证据；真实网络与fixture分标，不把截图内容预置为生产成功。 |

## 5. 关键技术实现说明

本节是开发约束与推荐接口，**不是已提交的Swift实现**。命名可按仓库约定微调，职责和状态语义不能省略。

### 5.1 展示模型与来源精简（F01/F03/F06/F14）

引入集中展示投影，例如`ArticlePresentation`与`VocabularyContextPresentation`。输出短来源名、作者、显示标题、紧凑日期、词数/时长和必要状态。数据层完整attribution、rights evidence、URL、rawContent、structuredBody保持原样；不能在View里用字符串前缀切割来猜来源，也不能为隐藏URL删掉数据库字段。

标题规范化在明确的Feed XML、CDATA、HTML/JSON-LD边界处理实体。记录原始表示和规范化版本，限定解码步骤，禁止对任意文字循环无限解码；保留合法字面`&`、比较符或技术文章中的实体示例。旧记录若只为显示而纠正，优先新增可逆displayTitle/投影，不更新正文hash和分配身份。

上下文归组键至少包含articleID、来源类型、句子范围/上下文ID；同标题并不等于同来源，同URL也不等于同句子。保留多来源、多句和未知历史类型。默认只展示一次短来源与文章标题，真正原句仍是可点击英文；原始溯源去关于/来源详情，而不是公开浏览器阅读入口。

### 5.2 统一书库状态、计数与发现（F02–F05）

`ArticleLibraryFilter`明确scope(all/favorite/later/history)、source、topic、query、sort；Repository或独立查询服务给出同一事务快照中的totalReadable、visibleCount、favoriteCount、laterCount。分页只限制渲染集合，不影响总计。收藏/稍后是独立布尔值，不能改成互斥状态。

`DiscoveryProgress`建议包含`runID`、`phase`、`totalSources`、`processedSources`、`activeSourceIDs`、`importedCount`、`duplicateCount`、`failedCount`、`terminalReason`。服务提供主Actor快照或`AsyncStream`；网络与解析仍在Service/Provider，View只订阅。最多三条来源管线的事实要准确表达，不能把每个URL当一个来源计进度。

| 状态 | 面向用户的表现 | 不允许的表现 |
|---|---|---|
| 准备 | 正在检查来源，必要时不定进度 | 虚构已完成百分比 |
| 运行 | 已处理3/13来源，当前BBC/NPR等，已新增N篇 | 显示未合格候选标题/URL；把等待当卡死 |
| 部分成功 | 新增N篇，部分来源暂不可用，可继续本地阅读 | 一家失败清空其他成功文章 |
| 无新文章 | 已完成检查，无新文章，本地版本可读 | 伪造新增数或错误清库 |
| 限流/全部失败 | 简短失败说明、可重试/稍后再试 | 不受限无限重试或冒称联网成功 |
| 用户取消 | 已停止，已入库N篇保留 | 取消后旧任务回调再刷成功状态 |

进入/离开某个View只订阅/解除订阅；显式取消操作与服务任务所有权分开。runID过滤过期事件。同一发现操作被多个入口共享时，一个View的disappear不能误取消另一个页面正在使用的管线。未知总字节只用不定下载状态；来源处理进度达到100%表示已处理，不表示全部来源成功。

### 5.3 正文清洁、原文保全与旧版本（F07）

当前通用提取排除script/style/nav/button，但视频fallback仍可进入正文。按源DOM的播放器容器、video/noscript、字幕/图注和articleBody边界区分正文与控件。保留正常媒体说明、记者引述和技术报道。规则必须有拒绝误删的反例，不许用“见到JavaScript就删除整段”的黑名单代替结构判定。

新抓取：源根选择→非文章节点分类→完整原文结构化→原文/结构一致性与完整性→原子入库。规则与extractionVersion有版本。旧记录先备份；低风险采用`ReaderDocumentProjection`隐藏已明确识别的非文章块，维持显示偏移→原始UTF16映射。需要替换存储正文时走内容版本事务：旧raw/structured/hash/署名和相关范围保留，不改冻结复习上下文、已完成证据和旧日志；不能直接覆盖旧每日文章后让旧完成证据失配。

无法安全判定的段落不自动删除，先记录源级诊断并修正适配器。网络失败不替换已有全文；重新提取失败保留旧版本。不得加入原站、摘要或URL降级。

### 5.4 词身份、可靠义项与真实Provider链路（F09/F10/F16）

先确认生产启用和请求：`AppDependencies.makeProduction`已有`enableOnlineProviders`，不能声称缺少在线实现。已确认的问题是：`VocabularyDetailView.lookup`未传语境；快速释义只要有中文就过滤掉英语义项；`ReviewQueueService.primeMeanings`仅`localResult`，题组读取`DictionarySenseRecord`中的反向中文，不能因英语Provider联网通过就认为复习答案可靠。

建议抽出三层策略：

1. `LemmaResolution`：保留sourceSurface、canonicalLemma、caseClass、POS/词形证据和可信度；用户/访问类可靠复数还原，但不机械删s。专名和月份的大小写语义不能在最初lowercase时丢掉。低置信度不要强合并。
2. `SenseSelectionPolicy`：先按同词元、大小写语义、词性和原句确定候选，再按可靠组和字段证据排序；网络快慢不是优先级。可靠词义与个人义分开，前者存在即禁用个人编辑；只有无可靠来源才允许确认个人sense，CC最低。融合需保留字段级来源，不能拼接不对齐义项（F23）。
3. `ReviewSenseResolver`：只选择具有稳定senseID、语境对齐和中文依据的答案；中文依据仅限可靠源原文，或F23资格允许且已确认的个人中文sense。不可靠/重复/缺义返回结构化可处理结果交F08，不能只从本地反向索引取第一个字符串。

可靠中文的数据路线是明确开发项：复用现有Wiktionary接入，调查并解析原始词条/翻译章节中与英语sense、词性相对齐的中文，保存页面/revision、sense/gloss、中文原文、来源许可与缓存版本。不存在可核验中文时，不由Free Dictionary英语义自动翻译，也不拿反向碎片凑数；已有可靠英文仍禁止个人补义并按F08重试/延期。只有无可靠来源的词可录入/确认结构化个人义，满足F24合同后才成为复习依据。只有当解析和真实样本能证明对齐时启用自动答案，无法证明则必须降级为候选并进入F08，不能虚报中文链路已完成。

官方技术调查入口：[Wiktionary翻译结构](https://en.wiktionary.org/wiki/Wiktionary:Translations)、[MediaWiki parse接口](https://www.mediawiki.org/wiki/API:Parsing_wikitext)、[Wiktionary许可](https://en.wiktionary.org/wiki/Wiktionary:Copyrights)。这些页面仅证明存在可调查的结构/API及许可要求，**不证明任意词都有中文、不证明中文映射已实现**。不得为了本轮引入必须付费或由负责人提供Key的硬依赖。

Provider状态独立记录success/empty/failed/cache/stale、版本和最近尝试；完整缓存的定义不能把暂时空结果固化成永不重试。优先展示可用缓存，再按版本/TTL/显式重试获取缺失来源；保留single-flight、取消和word/request generation保护。只有一个来源时显示“来源：…”；真实多个不同来源才叫“已合并”。简明层不堆长错误墙，完整页可看细节和重试。

### 5.5 自动保存的事件、事务和恢复（F09/F20）

使用独立`AnnotationAutosaveCoordinator`及`PreferencesAutosaveCoordinator`，共享`SaveState(clean/dirty/saving/saved/failed)`思路，但不得把生词保存、偏好保存、查词失败共用同一个字符串。服务拥有任务生命周期，不能依赖即将消失的View启动一个随后被取消的提交。

下表中“释义”仅指F23策略允许编辑的个人字段；有可靠来源时只保留笔记等合法编辑，不因自动保存流程重新开放释义。

| 事件 | 生词释义/笔记 | 设置 |
|---|---|---|
| 初始加载/程序回填 | 建基线，不写回 | 建基线，不写回 |
| 输入中 | 标dirty；不提交未上屏IME文本 | 文本短防抖，保留有效性判断 |
| 焦点切换/完成输入 | 提交变化快照 | 文本提交 |
| 拖动/点空白/系统收键盘 | 无论是否点完成按钮都flush | flush |
| 返回/切Tab/转后台 | flush；失败保留草稿和错误，不能静默丢失 | flush有效变化，不重写既有周期 |
| 开关/Picker/Stepper | 不适用 | 有效改变即提交，快速连续操作合并 |
| Slider结束 | 不适用 | 结束或短防抖提交，最后值胜出 |

每次提交携带entryID/setting key、baseRevision和draftRevision。相同已保存快照不重复写，旧提交结果不能给新草稿显示成功；未提交变化不被后到词典查询覆盖。失焦与键盘通知重复触发只合并一次逻辑提交，允许Repository保持幂等。

失败必须区分“当前编辑值”和“已持久有效值”。保留原值、草稿及重试，不先显示勾号。要求意外重启恢复未保存编辑时，可采用独立Application Support原子草稿文件/模型，记录baseRevision并按系统数据保护保存；该草稿不是可清理缓存。数据库本身不可写时不能声称把草稿也写入同库成功。重新打开若发现基础数据已变，提示冲突而非静默覆盖。无需声称强杀瞬间尚未落盘的最后一字必定可恢复，验收要使用明确“草稿已落盘”检查点。

资格允许的个人释义改动仅影响以后新题组；有可靠来源即禁用新增/编辑，旧个人义只读保留且不用于新题。既有有效题组按冻结快照，已证实错误题按F24明确暂停处理。偏好修改从同一PreferencesRepository提交并在成功后广播revision；时区/上限不改旧周期日期/原题量，autoAdd不追溯删除旧词。

### 5.6 复习入口、错误与合法延期（F08）

`prepare`返回类型化结果，例如ready、nothingDue、needsMeaning(entryID/reason)、invalidSession、storageFailure、networkUnavailable。当前泛用`LearningError.invalid(String)`需要在服务边界映射结构化类型，不能在View靠中文substring判断可否忽略。

今日进入和Tab选择共用预检协调器，保存来源页面与进入意图。异步预检未结束时不先呈现练习；取消回原页面。若来自复习Tab，可保留原Tab选择直到ready再切换，错误弹窗归统一容器管理。已进入有效会话后后台恢复失败，要保留最后有效快照并阻止不安全提交，不能清空成“请先积累词汇”。

| 错误类型 | 操作 | 禁止的行为 |
|---|---|---|
| 可定位缺义/重复中文词 | 取消、本次延期、选可靠义/重试；仅无可靠来源可立即补录结构化个人词 | 有可靠英文也开放个人补义、删除生词或拿弱义项强出题 |
| 网络无缓存 | 取消、重试、本次延期；既有个人编辑资格须经F23判定 | 把超时/离线当无词、给已知可靠词开放个人补义 |
| 保存/读取失败 | 取消、原动作安全重试/恢复 | 忽略整个数据库错误并完成周期 |
| 会话损坏/版本未知 | 退出、保留证据、经过校验的恢复 | 自动删库或假设所有题完成 |
| 真正无到期词 | 清晰无任务状态 | 与用户手动跳过混为一谈 |

本次跳过记录`session/cycleID + entryID + reason + timestamp + scope=currentSession`，按已有延期语义扩展，不创建“答对”记录，不改该词FSRS或删除原词。保存原始候选集合、有效应答集合和跳过集合；全跳过再次确认，结论为明确延期而非“0题全部答对”。门禁只能依据真实完成和用户明确合法延期判断该次任务已处理；延期在统计中单列。下次符合条件的复习仍可处理该词，补义后可新建题组，不能把当前会话skip当永久封禁。

### 5.7 题目、反馈与揭示后纠正（F11/F12/F18/F19）

用`ReviewQuestionState`与`FeedbackToken(sessionID,questionID,attemptID,revision)`替代全局feedback字符串决定当前题正确与否。每次题目切换清空输入/提示/错误/提交状态；显示上一题结论只能在明确的上一题提示区，不能挂在当前题下。

| 当前状态 | 允许操作 | 反馈与持久化 | 可否推进 |
|---|---|---|---|
| answering | 输入、提交、提示、显示答案 | 无旧题成功反馈 | 否 |
| submitting | 等待事务 | 不可重复提交，未成功无绿勾 | 否 |
| incorrect | 重试、提示、显示答案 | 同题错误与尝试数 | 否 |
| hinted | 继续作答 | 提示证据固定，评分不高于Hard | 正确后 |
| revealedAwaitingCorrection | 亲自输入已显示答案 | 保存揭示事实，保持同题，评分固定Again | 否 |
| correctionIncorrect | 继续输入 | 同题、无新一次复习事件 | 否 |
| correctionSubmitting | 等待纠正事务 | 未保存前不完成 | 否 |
| answered | 下一题或受控推进 | 已保存结果绑定本题 | 是 |
| saveFailed | 保留输入、安全重试 | 无虚假成功/完成 | 否 |
| sessionCompleted | 返回/查看次级记录 | 简洁摘要，日志仍存 | 已结束 |

显示答案不自动填输入框、不自动completedAt。新增revealedAt/correctionRequired/correctionCompletedAt或等价持久状态；纠正答案验证复用冻结acceptedAnswers，不能把近义词误当拼写变体。revealed后即使抄对也仍Again。完成纠正时只推进一次，对一个词的一轮评分、排程和不可变日志保持幂等；不要为纠正录入新增一条“Good复习”。

掩码从BasicReviewScheduler的旧尾部工具分离为SpellingMaskPolicy；这不是重写FSRS。创建题组时保存seed、maskIndices、maskVersion，默认隐藏25%–45%有效字母；对短语保留分隔符，短词明确边界。正文字境可以遮整词，单词提示内部掩码可分布前/中/后，两个层次不要混用。旧会话保存prompt优先，不迁移时重随机。默认词内补全仅选至少3个英文字母的目标；1–2字母仍可匹配但不为凑数生成含糊拼写题。隐藏数取有效字母数×0.35四舍五入并限制在1至字母数减1之间，按保存seed洗牌合法字母位置选取；固定语料/多seed测试验证前中后覆盖，而不要求每个短词都同时挖三个区域。

### 5.8 小浮层、整合详情与推荐（F13/F15/F17/F21）

从TextKit点击回调获得词范围与锚点矩形，经坐标空间转换到Reader容器。只用公开SwiftUI/UIKit API，选择系统popover并允许紧凑设备popover适配，或实现原生锚定overlay。根据可用safe rect在词上/下选位置并夹紧边界，旋转/滚动/动态字体更新锚点；不能写死全屏x/y或直接拿截图像素当point。

浮层显示`CompactWordPresentation`：英文/IPA、最多两条真实语境义与词性、membership(action/status)、details action。长来源、技术状态、完整原句、所有短语和额外字段进入全屏。点击外部关闭不滚动回开头；快速换词用新的selectionID隔离结果。读者为视觉背景保留可辨上下文，无障碍焦点移入浮层，关闭恢复原词；详情与嵌套层不同时暴露重复关闭按钮。

加入状态至少区分notAdded、saving、addedByThisOperation、alreadyExisted、failed。勾号只在真实落盘后显示；撤销token绑定本次新增的entry/source relation，不能凭当前词面字符串删除。已有词不提供误导的“撤销本次加入”。设置关闭autoAdd时仍可明确加入，推荐与其详情默认不自动加入。

统一`WordDetailContent`按F22的3图层级承载完整可靠sense/词性/IPA/例句/短语、资格允许的个人内容、笔记和简化来源；生词详情直接复用，Reader小卡右箭头开新全屏容器。领域/查询/持久化不搬到View。不同来源义项不只因中文相同就合并，缺失字段按可靠性隐藏或短提示。推荐词卡只显示英文、IPA、可靠中文简义，点卡统一进入详情；文章卡与词卡共享视觉token但不共用不适合的字段堆叠。

| 词形规范化 | canonicalEntryID/alias、lemmaResolutionVersion、case/POS证据 | 用户义/笔记冲突保留并显式解决；不删旧entry，旧题和日志引用仍有效 |

迁移前保留现有冷备份路径；内容或canonical映射写失败必须整体回滚。旧store能继续读或有可验证恢复方式；记录迁移版本和数量，不记录用户正文/笔记到日志。跨进程并发不在本轮扩展，但同一App内任务的重复请求和过期结果必须隔离。
