## 功能一：多来源英文文章自动发现与本地阅读系统（P1，核心新功能）

### 3.1 产品目标

用户打开词光后，不再只能看到 RFC，而是可以在本地文章库中阅读来自多个合格来源的真实英文全文。

候选来源审查范围必须完整覆盖：

- BBC News
- Reuters
- AP News
- The Guardian
- NPR
- Deutsche Welle（DW）
- VOA Learning English
- NASA
- Wikipedia / Wikinews

这些是**待审查候选来源，不是无条件启用名单**。每个来源必须核实官方 API/Feed 的实际全文字段、授权条款、全文下载权、本地持久化权、离线访问权和 App 内展示权。只有全部满足才可启用。

**唯一允许的产品路径：取得完整、未经删节的原文 → 验证合法本地保存与展示权 → 完整性检查 → 原子写入 SwiftData → 只从本地数据库阅读。**

明确禁止：

- 原站阅读、WebView、Safari/浏览器跳转。
- 仅保存网址、标题或摘要。
- 只保存 RSS item/description。
- 部分正文、节选、预览、截断文本。
- “全文获取失败后显示摘要/链接”的降级方案。
- 先把 URL/摘要显示给用户、以后再补全文。
- 用 AI 摘要、改写或翻译代替完整原文。
- 把只有元数据的候选保留在推荐池、搜索索引、文章库、探索页或每日任务中。
- 通过绕过登录、付费墙、验证码或访问控制取得内容。

如果某来源不能满足全文准入条件，**直接舍弃该来源或该文章**：不得入库、不得进入推荐/搜索/文章库/每日任务，不得给用户显示可点击的候选条目。不能为了来源数量而采用其他方式。

目标是在合法可用范围内尽可能接入至少 5 个完整全文来源。必须逐一审查全部 9 个候选；若真实授权条件不足以达到 5 个，按事实排除不合格来源并提交逐源审查报告，绝不能使用摘要/网址等替代方式凑数。此要求不减少本轮其他五个功能模块、全部 Round 2 整改、测试和截图工作量。

### 3.1.1 来源接入方式

允许的技术入口仅限于来源官方提供、且明确允许获取完整原文并本地保存/展示的方式：

1. 官方完整内容 API。
2. 明确提供完整正文且授权范围允许保存的官方 RSS/Atom Feed。
3. 正式授权的内容服务或书面许可。
4. 其他经审查确认允许完整复制、持久化、离线访问和 App 内展示的官方渠道。

RSS、Atom、Sitemap 或网页列表如果只提供元数据/摘要，只能作为内存中的技术发现输入，不能成为产品内容。不得对不允许的网页进行爬取，不得绕过官方 API 的授权限制。

候选入口：

- BBC Top Stories：https://feeds.bbci.co.uk/news/rss.xml
- BBC World：https://feeds.bbci.co.uk/news/world/rss.xml
- BBC Technology：https://feeds.bbci.co.uk/news/technology/rss.xml
- DW Top Stories：https://rss.dw.com/rdf/rss-en-top
- DW All English：https://rss.dw.com/rdf/rss-en-all

这些地址仅用于调查和核实，不代表授权全文，也不代表这些 Feed 一定提供全文。Reuters/AP 必须从官方渠道核实正式全文产品和许可。

### 3.1.2 全文准入审查

建立 ArticleSourceEligibilityAudit，至少记录：

- sourceID / sourceName
- officialEndpoint
- officialTermsURL 或授权证据
- fullTextFieldVerified
- fullTextFetchVerified
- localPersistenceAllowed
- offlineAccessAllowed
- inAppDisplayAllowed
- attributionRequirements
- cacheDurationOrRestrictions
- reviewedAt
- decision（eligible_full_text / rejected / pending）
- rejectionReason

默认一律为 rejected/pending；只有证据完整且审查通过才能启用。不能把“HTTP 200”“RSS 能打开”“网页浏览器能读”当作全文授权证据。

### 3.1.3 技术架构

建立或扩展：

- ArticleSourceRegistry
- ArticleSourceEligibilityAudit
- ArticleDiscoveryService
- RSSParser
- OfficialAPIAdapter
- ArticleFetchService
- ArticleHTMLExtractor
- ArticleDocumentNormalizer
- ArticleQualityValidator
- ArticleRepository
- ArticleRecommendationService

优先复用现有 ContentRepository、ArticleCandidateProvider、LearningServices，不得重复建立第二套每日任务状态机。

来源配置至少包含 sourceID、sourceName、官方 feed/API、category、discoveryMethod、fullTextContentMethod、refreshInterval、fullTextStorageAllowed（默认 false）、权利证据、lastSyncAt、ETag/Last-Modified、lastError、enabled。只有审查为 eligible_full_text 的来源才允许 enabled=true。

### 3.1.4 自动发现、完整正文获取和入库

必须实现：

- App 启动时按需刷新合格来源。
- 今日/探索/文章库页面进入时检查缓存新鲜度。
- 用户手动刷新。
- iOS 后台刷新作为尽力而为能力，不依赖固定时间执行。
- RSS/Atom XML 解析和官方 API JSON 解析。
- 发现候选仅临时驻留内存，不创建持久化文章记录。
- 取得完整原文后才执行规范 URL、去重、结构化和数据库事务。
- 标题、作者、时间、来源和分类只作为完整文章记录的元数据保存。
- 正文获取与候选发现分离，但不得把候选发现结果展示给用户。
- HTTP 304、ETag、Last-Modified。
- 超时、限流、断网和错误处理。
- 有上限的并发和指数退避。
- 一个来源失败不能导致其他合格来源失败。
- 新文章只有在完整原文与权利校验全部通过后才允许原子入库。

### 3.1.5 正文提取

对已获准取得完整原文的来源：

1. 优先官方 API 结构化正文。
2. 再使用明确授权的完整 Feed 正文。
3. 再使用允许的 JSON-LD NewsArticle/articleBody。
4. 再使用允许的 HTML article/main/p/h1/h2/blockquote/ul/ol。
5. 必要时使用 Readability 思路的提取器或 SwiftSoup。

过滤网页导航、广告、Cookie、推荐卡片、评论区、订阅引导和重复模块，但不得删掉文章本身的段落、引用、列表、修正声明和必要署名。

完整原始正文必须保留；结构化正文仅负责排版，不得摘要、改写、翻译、删节或缩短原文。

不得将登录页、验证码页、403/429 错误页、摘要页、预览页或截断页面当作文章。

### 3.1.6 本地数据库

继续使用 SwiftData。ArticleRecord 只允许保存通过权利和完整性验证的完整文章。

必需字段：

- articleID
- sourceID
- canonicalURL（只作完整文章的内部溯源和去重，不能单独构成记录或跳转阅读）
- title
- author
- publishedAt
- fetchedAt
- rawContent（完整原始正文，必填）
- structuredBody（完整原文结构，必填）
- bodyHash
- wordCount
- estimatedReadMinutes
- topicTags
- fullTextRightsEvidenceID
- extractionVersion
- completenessVerifiedAt

不得保存 summary、excerpt、preview、originalLink、webViewURL 等替代阅读字段。候选元数据不写磁盘、不进入搜索索引。

数据库约束和 Repository 写入入口共同保证 rawContent、structuredBody 非空且完整性验证通过后才可创建记录。原文和结构化内容必须原子写入。

### 3.1.7 失败处理

遇到以下任一情况：没有全文权限、只有摘要、只返回部分正文、截断、解析失败、登录/付费墙、验证码、403、429、正文语言/内容不合格、数据库写入失败：

- 丢弃当前候选。
- 不创建 ArticleRecord。
- 不保存候选标题、URL、摘要或节选。
- 不在文章库、搜索、推荐、每日任务或探索页展示。
- 不提供外部跳转、WebView 或原站阅读。
- 可记录不含候选正文和 URL 的 sourceID、错误类型、时间和诊断码。
- 如果更新的是已有有效文章，保留旧的完整本地版本，不得用不完整新版本覆盖。

失败 UI 只允许显示通用提示，例如“无法导入完整文章，未添加到本地文章库”，不得展示不合格候选的标题、摘要或网址。

### 3.1.8 文章库与推荐 UI

新增或升级真实文章库：

- 按来源、主题分类。
- 按时间排序。
- 搜索完整入库文章标题。
- 显示文章长度和预计阅读时间。
- 显示来源、作者和发布日期。
- 只显示已验证完整全文且本地保存成功的文章。
- 已读、未读、正在阅读状态。
- 收藏/稍后阅读。
- 离线可读标记（所有文章都应本地可读）。
- 下拉刷新。
- 空状态、加载状态、通用错误状态和重试状态。

不允许出现“摘要可读”“原站阅读”“点击前往官网”“全文暂不可用”等内容卡片。

### 3.1.9 每日学习整合

- 如果存在未完成周期，继续旧周期。
- 只有没有未完成周期时才创建新周期。
- 新文章分配必须原子化。
- 预取候选不能算已分配或展示。
- 只有完整入库文章才能进入每日文章候选池。
- 文章获取失败不能伪造完成。
- 用户已开始阅读的文章不能因刷新而被覆盖。

### 3.1.10 验收

## 功能三：真正可视化的连线复习题（P1，用户明确要求）

### 3.3.1 当前缺陷

- 正确连接线保留至本题结束。
- 选项位置变化时连接线同步更新。
- 选择/正确/错误/完成状态不能只依赖颜色，还要使用边框、符号、文案或线型。

连接关系至少保存 questionID、leftOptionID、rightOptionID、state。实际答案正确性仍由 Domain/Service 判断，View 不能自行决定正确答案。

- 错误匹配。
