## 3. 完整释义页的产品与视觉合同（F22）

### 3.1 页面骨架

| 顺序 | 内容与交互 | 缺失/边界 |
|---|---|---|
| 词条头 | 衬线词头、必要的原词形提示、英/美IPA、真实音频按钮；紧凑生词状态/加入动作 | 没有IPA不画假音标；无源音频时可另用系统朗读并明确标“系统朗读”，不能称原声 |

| 词性/词源分组 | A/B/C或等价易读序号、noun/verb等标签；真实及物/不及物、可数性、词形变化附组头 | Provider只给verb时不臆造两套vi/vt；同拼写不同词源/读音保留边界 |

| 搭配与例句 | 搭配/句型缩进；英文重点使用衬线/适度粗体；已有译文紧跟下一行 | 例句属于该sense；译文属于该例句；仅英文也完整显示，不拼接其他义的中文 |
| 短语/习语 | 短语动词、固定搭配、习语可分小节；实际词形变化、释义、用法和例句 | 只有真实数据才显示；点击相关短语走统一词典导航，保留返回位置 |
| 更多资料 | 可靠的近反义词、词根词源、用法辨析及其他原有资料 | 不造近义词差别或词源，不为每块空资料建一张空卡；原有AI区不扩成新开发范围 |
| 来源/状态 | 简短真实来源标签，展开查看数据集、修订、缓存时间、字段归属和必要许可 | 单源不称融合；部分失败不淹没正文，细节/重试放次级区 |
| 底部操作 | 轻量后退、当前词条、关闭；加入生词本可放头部右侧或独立紧凑工具位 | 不强行复刻3个按钮位置；不同入口后退/关闭语义必须正确，不重复堆导航条 |

“尽量包含最多信息”指接入层不能丢掉已获得的有效结构字段，展示层不能只取第一项；不等于强制每个词拥有全部字段，也不等于首屏同时塞满全部资料。完整内容可自然滚动/折叠分节访问，义项默认展开，特别长的来源详情可折叠。详情内查词、复制和发音保持已有能力。

### 3.2 排版、背景与无障碍

- 默认词头约28–34pt衬线，英文释义/例句约18–20pt，中文约17–19pt，辅助标签约13–15pt；统一采用可缩放文本样式，最终以同屏层级、美观和可读性验收，不能靠缩字号容纳一切。
- 每层缩进约12–18pt；小屏和大字适度减少缩进，不让中文剩一两字一行。词性间距约24–32pt、义项约12–18pt、例句组约6–10pt。英文/中文段落自然换行，不强制一行截断。
- 背景可使用克制的原生Material/渐变模糊，保持浅/深/暖纸三主题。降低透明度开启时提供实色高对比背景；浅色不能仅把深色字换白色。模糊不逐义项叠加复杂实时特效。
- 正文对比度目标≥4.5:1、大字及关键控件≥3:1；点击命中区≥44pt。标签有文字，不靠颜色区分来源和错误；状态栏与正文区安全隔开。
- 底栏采用真实safe area inset，内容底部留出栏高与可读间距；末行不得像参考图那样被遮。键盘出现时编辑区可见，旋转与大字下底栏能重排，必要时简化为原生工具栏。
- VoiceOver将词性、义项、例句/译文关联读出；圈号不是唯一语义。嵌套查词焦点与返回路径恢复，背景不重复暴露可点击元素。降低动态效果时不靠持续动画提示加载。

### 3.3 生词操作与入口统一

阅读器小卡仍只给简明义项和详情箭头，不把此丰富布局搬进小浮层。阅读器→全屏、推荐→全屏、生词→整合详情复用一份内容与来源资格模型，避免不同入口得到相反的编辑权限/复习义。

加入按钮的状态由Repository真实结果驱动：未加入、保存中、已加入、本次新增可撤销、原有词、失败。仅撤销本次拥有的新增操作，不误删原有词。推荐浏览和完整词典打开不自动加入；保留原阅读自动加入偏好。错误提示就近且克制，不另加一堵开发说明。

## 4. 可靠英中来源组、真实能力和融合（F23）

### 4.1 Provider策略与接入边界

| 来源 | 本次规定 | 当前代码/接入约束 |
|---|---|---|
| Wiktionary | 可靠优先组；优先完善英语词性、例句、短语、词源与可对齐中文 | 现有REST+Action适配已存在，中文sense对齐是待实现项；不是Wikipedia百科API |
| Oxford | 可靠优先组中的条件接入目标，必须调查与实现可配置适配边界 | 现仓库没有OxfordProvider；官方接口需要App ID/Key和相应可用数据权限。缺配置显示未配置，不假称已引用；不得把商业密钥硬编码进IPA/仓库 |
| Free Dictionary API | 可靠优先组，补充实际返回的英语义、音标、例句等 | 现有适配已存在；它的英语结果不等于可靠中文，暂不可用可明确显示并保留其他来源，不反复阻塞整个查询 |
| 其他英语词典 | 有真实数据链路、明确来源及审核后可加入同一组 | 不凭网页/品牌名称自动授予可靠身份，新增提供者要补版本/解析/失败测试 |
| CC-CEDICT反向候选 | 最低层补充候选，不属于本条“有可靠英中来源”的锁定依据 | 不能盖过可靠英语义，更不能自动进入复习中文金标 |
| 个人词义 | 无可靠英中来源时的用户内容，单独标记 | 不是可靠Provider，不伪标牛津/维基；资格和最小复习合同见第5、6节 |

可靠组内部先按词身份、语境、词性与字段证据适配；同等条件默认稳定顺序Wiktionary→已配置Oxford→Free，不能按响应先后排序，也不能因品牌更靠前强行覆盖更贴切的义项。本文没有规定“牛津的任何义永远压过维基”。Oxford未配置时用实际可用的维基/Free，不能把付费或密钥申请变成本次其他修复的硬阻塞；不得创建收费订阅。

Oxford与Free是不同Provider；Free结果不能标成Oxford。Oxford官方API数据也不能笼统声称就是参考截图中的同一版本词典。凭据如未来已由负责人安全配置，通过已有配置层/受控代理获得，不由View拼请求、不打印到日志、不提交密钥。没有可用安全配置时只实现可插拔边界和真实未配置状态，不虚报Live通过。

### 4.2 数据与字段融合规则

1. 先确定`LexicalIdentity(language, lemma, caseClass, entryType, homograph/etymology discriminator)`，保留surface和POS证据；May/may、nod/nod off、词源不同的同形词不能为融合而抹掉身份。
2. 每个Provider保留自己的entry/sense/revision ID及原文、许可、fetchedAt。UI分组顺序变化不得重建senseID；不能用“第3条”作为业务主键。
3. 跨源同义合并要求概念一致且POS/词源/词形关系兼容。只因中文相同、词面相同、都带verb或embedding相近不足以合并；不确定时并列保留，允许用户选择已有可靠sense。
4. 英语定义、中文翻译、音标/口音、例句/译文、语域、词形、词源分别保存字段来源。另一来源的中文只有具有明确同义映射证据时才能挂到这个sense；否则不能装成原义的双语翻译。
5. 同例句去重保留全部来源引用；不能把两个不同句子和一条译文凑一组。API只给英文例句时如实展示英文。音频/IPA要同一词条/口音，不把名词读音套给不同发音动词。
6. 语境排序只调显示/建议位置，不删除其他义项；“来源：维基”只在真实内容来自维基时出现。多源字段融合可用轻标签，完整来源关系在展开详情查询，避免回到冗长URL墙。

建议引入`ProviderEntrySnapshot`、`LexicalSense`、`SenseFieldProvenance`、`SenseAlignment`、`DictionaryDetailPresentation`。扩展现有DictionarySense与Provider解析，原缓存JSON必须可兼容解码，缺失字段以optional/default表示；不是在View里把几串文字粘在一起。

## 5. 用户释义资格与结构化录入（F23）

### 5.1 “有可靠英中来源”的操作定义

对同一词条身份，任一已审核Provider有**真实、非空、与英文身份匹配且含中文的sense**，才具有可用可靠英中来源。只有发音/一个URL/品牌名/错误页不构成可靠定义。可靠中文缓存同样算；只有英语定义而无中文不算，也不展示英英定义。锁定粒度为整个对应词条身份，不按缺失字段或某个尚无翻译的sense开后门。

“禁用用户释义”包括创建、修改、追加个人sense/POS/例句及用个人义覆盖当前复习义，不能只把一个TextField变灰。可以选择已有可靠义项，并编辑独立的个人笔记。笔记不进入标准答案、不伪装成个人定义；旧个人内容和已落盘草稿仍保留只读可导出，不自动迁移进笔记作为绕过。

| 资格状态 | 用户释义 | 笔记/查词 | 复习动作 |
|---|---|---|---|
| reliableAvailable / 可信缓存 | 禁止新增、编辑 | 可记笔记、选已有可靠sense | 满足中文/语境合同则出题 |
| englishOnlyNoChinese | 允许结构化个人英中录入 | 英英定义不展示；可保留真实音标/词形/例句 | 确认个人中文/POS/语境后可出题，否则补录/重试/延期 |
| knownReliableUnavailable | 禁止；过期不可用或网络失败不等于从未存在 | 保留可合法使用的缓存；已知存在标记与学习证据持久保存 | 可恢复已冻结有效题；新题无可用证据则延期 |
| confirmedNoReliableEntry | 允许结构化自建 | 展示自建标记/可选最低层候选 | 确认并满足合同后可用个人sense |
| checking / unknownFailure | 没有已知可靠中文时可由用户明确补录个人英中义；不声称词典未收录 | 重试并保留来源失败/草稿状态 | 补录需确认后才出题，不把超时当权威查无此词 |

`confirmedNoReliableEntry`表示可用来源明确无结果，且无已知可靠中文；网络未知状态不能冒用此状态，但无已知可靠中文时仍可由用户明确补录个人条目；未配置的Oxford不是一个永远等待的Provider。404等“无词”与超时/429/503/解析失败分别记录。已有经确认无来源且允许自建的词可离线继续编辑/复习，直到收到可靠内容的确证；不能因每次断网让既有个人词不可用。首次全失败不宣称任何来源未收录；没有已知可靠中文时，用户仍可明确录入标为个人来源的中文，不能伪标可靠词典。

可靠结果一旦出现，保存`reliableEntryKnown`与关联证据，不随普通缓存清理删除。失败不撤销可靠身份；确实对应错词/失效数据需要有明确校验和迁移记录，不能由View临时清布尔值。过期后数据不能继续使用的情况遵循来源能力，但不恢复个人编辑权来伪补原词。

### 5.2 结构化个人词条编辑合同

仅在`PersonalSensePolicy.manualAllowed`时开放。使用逐义项编辑卡和“添加义项/添加例句”等紧凑操作，不堆成单一巨大文本框；同样优先美观、焦点清晰和键盘可达。

| 字段 | 录入与保存 | 是否为复习必需 |
|---|---|---|
| 词身份/lemma/短语及surface | 继承当前词，变更身份需显式处理，不能混改另一词 | 必需 |
| 词性、可选语法标签 | 受控POS枚举+未知；及物/不及物/可数性/语域可选 | 已确认POS为出题必需；未知可存草稿 |
| 多义项 | 每义独立UUID、顺序、中文释义、确认状态、revision；不要求英英义 | 连线需明确、非空中文及选定义项；仅英文例句或音标不足以出英中题 |
| 例句与中文译文 | 多条配对记录；译文可缺；明确标“个人例句” | 有文章原句可用原句；无文章时拼写需可校验的个人例句 |
| 搭配/短语/用法标签 | 可选列表，关联具体义项；短语可独立建条 | 非必需，不能被当任意拼写同义答案 |
| IPA/发音备注/词形 | 可选实际输入；用户音标标用户填写，无源音频不造URL | 非必需；词形参与答案需显式验证 |
| 个人笔记 | 与个人义独立、所有词都可编辑 | 不作答案 |
| 系统字段 | origin=personal、createdAt/updatedAt、meaningRevision、确认时间、策略版本 | 必需，不允许用户伪填Provider身份 |

用户输入按文本渲染，长度与行数有可见校验，不执行HTML/脚本；未知不是编造。保存允许不完整草稿，并清楚说明哪些字段尚不足以复习，不能让用户误以为保存就等于复习资格。自动保存持久化内容与“确认作为学习义项”是两个概念；可将当前保存义项明确选为学习义，后续编辑产生新revision。

### 5.3 持久化、竞态与迁移

现模型`VocabularyEntryRecord.userMeaning`只有字符串，不能承载多词性/例句；已有reviewMeaningSenseID/Text/Evidence也不是完整个人词典。建议新增关联`PersonalSenseRecord`、`PersonalExampleRecord`及可选搭配记录，保留entry关系、senseID、revision和来源类型；或等价版本化结构，但要能原子保存父义项与子例句。

Domain统一`PersonalSensePolicy.evaluate(identity, providerEvidence, policyRevision)`，Service协调查询/编辑，Repository在每次保存及复习选义再次校验资格。提交携带baseRevision、draftRevision、policyRevision；可靠结果在编辑中到达则立即切只读，进行中的迟到提交也必须被拒绝/隔离，不能只禁用界面。未提交草稿保留、提示已获得可靠资料；笔记独立提交，不受个人义锁定影响。

自动保存继续覆盖失焦、键盘隐藏、返回、切Tab、后台，处理IME与版本顺序；只对合法的用户释义字段执行，失败不得显示成功。旧字符串迁移为`legacyPersonal`义项，原文字逐字保留，POS未知不猜，已有选义/日志保持可追溯；无来源词需确认/补字段后才新出题。有可靠英中来源的旧个人义保留只读历史，不被自动删掉，也不再作为新题依据。导出JSON/CSV要包含结构化个人义及其来源、版本/确认状态，旧导出兼容策略在实现前列出。

## 6. 与连线、拼写、FSRS和周期的统一合同（F24）

### 6.1 一份词义身份贯穿整条链路

`DictionaryDetailPresentation`、`CompactWordPresentation`、`VocabularyItem`和`ReviewSenseResolver`共享同一词身份与sense选择语义。不要出现详情显示维基动词义、简明页只拿CC中文、复习又取本地第一个名词义的三套规则。

新题可使用的依据只有两类：①可靠Provider的同义项、可靠中文和语境匹配证据；②没有可靠英中来源、个人编辑资格成立、用户已明确选定且字段满足合同的个人sense。其他来源/笔记/自动生成译文均不能自动成为标准答案。

| 数据情况 | 连线/拼写处理 | 预检可提供的动作 |
|---|---|---|
| 可靠义项含对齐中文与真实原句 | 固定同sense，进入两阶段 | 选择已有可靠义（必要时） |
| 只有英英，无可靠中文 | 英英视为无可用释义，不自动出题 | 可填写结构化个人中文/POS/例句，或查可靠中文/延期；确认后才出题 |
| 无可靠英中来源，个人sense完整 | 标个人来源，固定选义/POS；句境可取真实文章或明确个人例句 | 可开始或选择个人义 |
| 无来源个人词仅单行中文/POS未知 | 可存资料，当前不满足新题合同 | 立即补录结构化字段、取消、本次延期 |
| 中文碰撞/多个义均可能 | 不强分成靠ID点对的假题 | 选择已有义/真实POS和语境区分；仍无法一对一则延期 |
| 数据库/会话损坏 | 保留最后有效状态，阻止不安全提交 | 取消、安全重试/恢复；无“忽略并完成” |

### 6.2 冻结快照与来源变化

建议题目持久化`ReviewMeaningSnapshot`：entryID、lexicalIdentity、senseID、meaningRevision、POS/语法标签、definitionEN/ZH、origin、provider/source/revision、选义证据、contextKind、article/contextID或personalExampleID、sourceSurface/range、acceptedAnswers、mask/version、policyVersion。现ReviewExerciseRecord字段可扩展或关联独立快照，不在每次UI刷新时重新取当前词典结果。

会话建立时原子冻结有效义项、题目/顺序、中文、原句与掩码。连线与拼写引用同一学习义；原文拼写仍保持合法原词形（如users），短语遮整段、may/May大小写语义保持。个人例句可供无文章词拼写，但必须明确标记来源，核验目标词/短语存在与范围；有多个同形出现需保存选中范围，不猜测first occurrence。不可从近义词自动扩展acceptedAnswers。

可靠英中来源在个人题进行中出现：锁定今后的个人编辑，新题改用可靠英中来源；进行中的有效旧题继续使用冻结个人快照并如实标记历史来源，不暗换答案。已证实旧题语义错误或数据损坏时暂停该题，明确取消/合法延期或受控重建，保留旧证据，不继续要求错误答案，也不悄悄抹掉尝试记录。历史已完成题与日志不追溯改写。

### 6.3 评分、恢复和门禁

个人义或Provider的修订不直接推进FSRS、不重置排程、不新建每日周期。现有每词复习状态保持；不要为了支持多个sense暗改成另一套排程算法。两阶段最终结果按既有规则汇总，使用同一幂等事件ID，只更新一次有效排程和不可变日志。

F19规则适用于官方词和个人词：显示答案后保留本题，亲自正确输入一次再推进，仍计Again；不是自动填答案、不是又记一次Good。F18反馈绑定session/question/attempt，任何来源都不能让上题绿色反馈残留在新题。保存失败保留输入/结果并安全重试，不能先显示成功。

无可靠中文的词可合法延期，保存本次范围、原因与用户确认，不计答对、不删除生词、不推进该词FSRS。全部延期与真正无到期词区分。词典打开、加入生词、选义、个人字段保存和Provider返回均不算复习完成，未完成周期继续优先，探索/推荐/书库门禁不因新页面而绕过。
